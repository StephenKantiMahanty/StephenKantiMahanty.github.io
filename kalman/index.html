03 / What the filter believes

R describes the assumed measurement noise; q describes the assumed acceleration noise. A larger R gives the sensor less influence. A larger q makes the motion prediction less certain. Changing these reuses the same sensor data. The leftmost q setting is zero.

Changing a setting pauses the mission and returns it to the start. Keeping the seed and real-world settings the same gives you the same measurements.

INSIDE THE ESTIMATOR

HOW THE FILTER WORKS

The white line lets us check the result, but the filter does not get to use it. It only has a model of the robot’s motion and the measurements. So it has to decide how much to trust each one.

Predict before you inspect

Select Dropout and inspect 19.8 s, 35.8 s and 36 s. What happens to assumed depth uncertainty while fixes are missing?

01

Predict the next state

The robot starts with its previous depth and speed. It uses the commanded acceleration to predict the next depth. Since the actual acceleration can differ from the command, the prediction also has some uncertainty.

Show the equationsd⁻ = d + h·v + ½h²·u
v⁻ = v + h·u
P⁻ = FPFᵀ + Q
02

Weigh the new fix

For example, the sensor might place the robot deeper than the prediction does. The difference is called the innovation. The gain K determines how much of that difference to use. Increasing R tells the filter that the sensor is less reliable, so it follows the measurement less.

Show the equationsy = z − d⁻   S = P⁻₀₀ + R
K = [P⁻₀₀, P⁻₁₀]ᵀ / S
03

Update the estimate

The filter adds the gain times the innovation to its prediction. This changes both the depth estimate and the speed estimate. If a measurement is missing, it keeps predicting. What this means is that the robot can keep moving, but the filter becomes less certain about its depth.

Show the equationsx = x⁻ + K·y
P = (I−KH)P⁻(I−KH)ᵀ + KRKᵀ

See a simple exact example

Let h = 1 s, acceleration u = 0, Q = 0, R = 1 m², initial [depth, velocity] = [0, 0], and P = identity. Predicting gives P⁻ = [[2, 1], [1, 1]]. A fix z = 3 m gives gain [2/3, 1/3]. The corrected state is [2 m, 1 m/s] and P = [[2/3, 1/3], [1/3, 2/3]]. Depth moves two thirds of the way toward the fix.

The model and its limits

One axis, fixed steps. State x = [depth (m), vertical velocity (m/s)]. h = 0.2 s; F = [[1,h],[0,1]], B = [h²/2,h]ᵀ, H = [1,0]. Initial state [7,0.1], initial P = diag(1 m², 0.04 m²/s²). Known commanded acceleration is 0.07 cos(0.2t) − 0.035 sin(0.4t) m/s².

Disturbance-consistent Q. Actual acceleration disturbance is independent Gaussian noise held constant per step. q is its assumed variance in (m/s²)², and Q = qBBᵀ = q[[h⁴/4,h³/2],[h³/2,h²]]. R is depth-fix variance in m². Standard deviation σ has the original units; variance is σ². Logarithmic tuning uses four significant figures; Match actual noise keeps the exact squared standard deviations, including q = 0.

What is a fix? A simulated, already processed localization depth fix, sampled every 0.2 s. This is not raw sonar range/bearing, underwater GPS, or DVL. No velocity sensor is modeled. Truth is used only for drawing and evaluation. Dead reckoning integrates commands with the same initial state and no fixes.

Confidence has assumptions. The ribbon is the marginal depth interval d̂ ± 1.96√P₀₀, approximately 95% for a calibrated Gaussian model. It is not a 2D ellipse or a safety guarantee. Current adds an unknown acceleration of +0.045 m/s² from 20–40 s; bias adds +2 m to fixes after 20 s. Both deliberately violate the zero-mean assumptions. Dropout removes fixes from 20–36 s.

Learning simulation. A prescribed depth transect, not closed-loop vehicle control, collision detection, or official RoboSub scoring. The gate, slalom, and bin references are simplified inspiration. Drag, attitude, full vehicle dynamics and correlated sensor errors are outside this model.
